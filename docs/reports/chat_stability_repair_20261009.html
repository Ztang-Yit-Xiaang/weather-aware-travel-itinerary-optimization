How to make this more stable

  1. Keep interpretation bounded. Resolve only supported edits with grounded stop IDs and exact parameters. Ask a specific clarification when part of the request is unknown. Add new language coverage through semantic examples, not broad text deletion.
  2. Preserve all clauses atomically. Stage the entire validated edit set or none of it. Validate the final order together; do not treat rows as sequential instructions.
  3. Keep independent evaluation. A schema-valid or well-understood reply is not proof that the itinerary is feasible. Continue checking constraints, weather, child identity, plan diff and rendered map before allowing acceptance.
  4. Measure semantic reliability separately. Count exact-meaning success, unnecessary clarification, dangerous substitution/omission, unsupported-action execution and reload mismatch. A high safe-refusal rate alone is insufficient.
  5. Grow an independent test set. Have another person write unseen paraphrases, negation, corrections, multilingual requests and mixed unsupported clauses. Freeze expected meanings before testing and keep these cases out of repair tuning.
  6. Exercise failure paths through the real UI. Retest timeout, malformed provider output, late completion, cancellation, double click, changed draft, deleted conversation, restart and reload. Existing focused checks cover parts of this; the complete project browser aggregate has not been rerun here.
