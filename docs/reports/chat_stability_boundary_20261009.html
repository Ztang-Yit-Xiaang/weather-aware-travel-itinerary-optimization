What was repaired

ProblemCurrent behavior
Two times were assigned by textual order.Explicit arrival and departure labels determine the bound. Departure 18:00 followed by arrival 09:00 yields arrival 09:00 / departure 18:00. The inverse invalid request is refused.
Latest arrival and earliest departure could become supported but different constraints.These unsupported bound directions require clarification, even when the request also mentions departure.
Extra duration, clock, range or alternative values could be silently ignored.A time-window or order shortcut must account for its numeric values; unresolved extra quantities require clarification before provider dispatch.
An old duration written first confused new-value extraction.The explicitly labelled old value is removed before extracting the exact new duration.

How this was tested

The 20 expected results were saved before changing production code. The first run failed 10 cases; its log is retained. The current 140-case semantic corpus runs through the deterministic adapter and the OpenAI adapter with an injected transport. Unsafe requests must make zero provider calls. The 242-check run also covers recorded prompts, provider mutations, real typed-edit API evaluation, memory and atomic stop ordering. A separate 43-check provider suite passes. These counts overlap earlier evidence and must not be added to it.

First failing run · 242-check passing run · 43 provider checks · Scoped static checks · Expected-case freeze

Six representative requests were also entered through the actual local website. The corrected time window was added to the isolated draft, recovered after reload, and undone. A final reload restored all six completed turns with an empty draft and the original accepted plan. No repair acceptance or booking occurred. The map is explicitly unavailable on this separate test origin; this checkpoint provides chat and draft evidence only. The existing map configuration was left unchanged.

What will make reliability measurable

  1. Keep a single typed contract as the authority for supported operations, targets and values. Any unresolved clause must remain visible as a clarification or unsupported request.
  2. Use the exact review card and independent evaluation before acceptance. Preserve atomic batches and reject stale responses or changed workspace state.
  3. Maintain separate measures for wrong-meaning suggestions, successful supported requests, safe clarification, legitimate feasibility blocks and transport failures. A safe refusal must not inflate supported-request success.
  4. Run a separately reviewed unseen English/Chinese/multiturn set on a frozen version. The cases used for this repair are development regressions, not blind holdout evidence.
  5. Run the proposed bounded live batch, then repeated source-frozen trials and the remaining full browser/keyboard/overlay checks. A single 14-message batch cannot establish general reliability.

Still open: fresh live-model accuracy, independent unseen paraphrases, the full regression and browser aggregate, and E2E-1/G5 acceptance. The existing proposed live batch remains unexecuted pending the previously requested approval.
