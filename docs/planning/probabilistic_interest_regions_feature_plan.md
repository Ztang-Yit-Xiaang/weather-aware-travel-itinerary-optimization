# 概率兴趣区域与必去点可视化方案

状态：`ready_for_local_prior_exploration_review`。更新：2026-10-21。当前可以在本机产品页面评审兴趣区域、具体地点和必去约束；模型仍为先验模式，真实反馈为零，未校准。

已实现贝叶斯逻辑回归的概率及 90% 参数不确定区间、完整有界地点集合、同色系连续密度、50%/80%/95% 模型质量区域、来源说明和独立的最深色必去点。地图有地点名称与 Browse places 入口，支持名称/类别搜索、区域内/全部周边筛选、键盘选择和定位。Day 5 有 18 个周边地点，Day 6 有 99 个及 1 个明确准备的示例必去约束。目录为 134 条有来源地点。

## 目标和边界

用户可以看到值得探索的范围，点击其中已有来源的 POI 查看概率和可行性依据，再经现有草稿、独立评估和接受流程加入行程。连续着色不表示区域内任意坐标均可游览。

本功能属于产品探索图层，不作为 E3/E4 优化方法比较或论文实验的完成证据。首版支持单日、指定路线段、当前接受行程；不改变现有效用函数、求解目标、约束权限或自动接受行为。新图层单独开关，默认关闭；关闭时沿用当前地图行为。

## 概率含义与模型选择

定义 `Y_ui=1` 为：在规定的展示上下文中，用户对可选 POI 明确回答“感兴趣”。`p_ui=P(Y_ui=1 | 用户偏好、POI 特征、上下文、反馈数据)`。它不表示必然参观、一定可插入行程或路线成功率。不同地点的兴趣事件不互斥，因此各地点概率不需要相加为 1。

推荐第一版采用贝叶斯逻辑回归：`Y_ui ~ Bernoulli(sigmoid(theta · phi_ui))`，对参数设置正态先验，并以 Laplace 近似得到参数后验。特征复用地点类别、明确偏好、天气适配和时间/绕路上下文；将当前效用作为可选特征或基线，不能把 UCB 数值直接变成概率。来源缺失应有显式特征或缺失掩码。

每个地点通过参数后验抽样得到 `p_ui` 的均值及分位数。分位区间是模型条件下对兴趣概率的不确定性描述；Bernoulli 的行为随机性与参数不确定性需要分别说明。该设计参考 [Stan 的后验预测说明](https://mc-stan.org/docs/stan-users-guide/posterior-prediction.html)，不要求安装 Stan。

| 候选方法 | 适合程度 | 本方案的取舍 |
| --- | --- | --- |
| 贝叶斯逻辑回归 | 首选基线 | 参数少、特征解释直接，可表示参数后验；表达能力和近似质量需要检验 |
| Gaussian Process 分类 | 后续对照 | 能表达非线性和相关性；类别、地理与上下文的核设计及较大样本成本更高 |
| XGBoost 分类及独立校准 | 数据积累后的对照 | 适合表格特征；输出概率仍需校准，参数不确定性需要额外方法 |
| 仅 KDE / GMM 平滑目录点 | 仅用于区域构造或外观示意 | 能形成连续密度，无法独立学习用户偏好 |

冷启动时只可显示“先验估计 / 未校准”，或者显示现有效用生成的“相对兴趣”基线并关闭概率百分比。先验可以来自用户明确的类别偏好；不得用评论数量、自动生成标签或点的组合数伪装真实反馈。数据支持不足时不显示“已校准概率”。

## 从点概率生成连续区域

对当前上下文中的完整、有界、可选 POI 集合逐个推断。必须记录候选全集哈希和截断状态；任何截断都改变分布含义，不能默默声称覆盖全城。

1. 对每次参数后验抽样 `m`，得到各 POI 的 `p_i^(m)`。
2. 对候选概率归一化，构造空间探索权重 `w_i^(m)=p_i^(m)/sum_j p_j^(m)`。
3. 以展示坐标为中心，使用以米或路线旅行时间为尺度的核 `K_h(s,s_i)`，得到连续场。
4. 在可信支持域 `M(s)` 内裁剪并重新归一化：`q_m(s)=M(s) sum_i w_i^(m) K_h(s,s_i) / Z_m`。
5. 对 `q_m` 求平均，得到 `q(s)`；选择阈值 `t_c`，形成高密度区域 `R_c={s:q(s)>=t_c}`，使区域累计质量达到 `c`。

`q` 是从已知 POI 兴趣概率构造的空间探索分布，不自动等于下一次实际出游位置的预测分布。若希望预测“接下来会选哪里”，需另设含“不选任何地点”选项的选择模型和相应标签。

50% 区域表示较集中的探索核心，80%/95% 区域包含更多模型兴趣质量。不要使用 `q(s)>=0.8` 代替 80% 区域；密度有空间单位，单点密度也不等于概率。

多峰区域允许形成多个不相连的岛状范围。用户需要的是连续色带，不必强行把所有点连成一个大面。平滑半径是空间设计参数，不能充当模型不确定性。

沿海、水域和不可达地形不能仅凭直线距离补色。首版仅在有依据的陆地/通行支持域内着色；缺少支持域时隐藏连续区域并保留已有 POI 点和“资料不足”。已知不可插入和未知可行性需要分开表达，不都赋为兴趣概率零。路线入口用于可达性检查，不能混作景点展示位置。

## 颜色与交互

- 区域采用一种色相的浅到深渐变，表示固定定义和固定标尺下的模型兴趣密度；具体 POI 的兴趣概率在点详情显示。
- 已确认的必去地点始终用该色系最深色，加菱形或锁标记及“必去”文字。模型数值保留原值，不写成 `p=1`，也不以巨大权重制造周边热点。
- 判断必去时解析规范的存在性/保留约束、`confirmed`、目标及强度。沿用评估器对 HARD/STRONG/LOCKED/BOOKED 的处理；单独的硬时间窗、时长或角色约束不直接等于必去状态。具体存在性关系映射在实现时以规范行程解析结果为准。
- 多个必去点距离很远时分别显示，不沿它们连成的走廊染色。必去但当前不可行的地点仍保留最深色，并显示文字冲突，不能用最深色暗示已经可行。
- 鼠标选中候选点只改变边框或尺寸；仅明确执行“设为必去”并经现有行程操作确认后，才进入最深色层。
- 图层顺序为底图、兴趣区域、路线、地点、必去标记。区域最高色阶预留给约束标记，避免重叠密度遮住必去点；保留地名和路线的可读性。
- 图例区分“模型兴趣密度”“必去约束”“未评估/资料不足”。探索图层可以显示兴趣，但添加行程仍走当前独立评估流程，不能直接标记 recommended。

[MapLibre 官方说明](https://maplibre.org/maplibre-style-spec/layers/#heatmap)中的 heatmap 根据加权点密度着色，数值与半径、强度等显示参数有关。可用它快速做外观探索，但正式的累计质量区域应由后端固定坐标网格/等密度面计算，再以 GeoJSON fill 等方式显示。缩放、平移不得重新归一化概率或改变区域的统计含义。

## 接口与集成

新增只读接口建议为 `GET /api/sessions/{session_id}/map/interest-regions`，沿用现有认证和 revision 检查。输入延续当前候选接口的日期、路线段、替换目标、角色及绕路预算，另接受覆盖质量等级。首版使用服务器配置的类别偏好先验和可选离线反馈快照，不新增在线行为收集或会话持久化字段。

响应已采用独立版本 `product-interest-regions-v1`，没有改写严格的候选 v1 协议。下面保留原设计的契约草案；实际字段以 `product_app/interest_regions.py` 和当前接口响应为准。三个质量等级均由服务端生成，等级切换在客户端完成；密度和区域 GeoJSON 位于 `surface` 内：

## 实施顺序与完成条件

1. 冻结预测事件、候选集、特征和证据模式；用当前效用建立明确标为相对兴趣的基线。无偏好标签时只验收冷启动模式。
2. 用版本化的真实反馈拟合贝叶斯逻辑回归，检查后验近似与校准。反馈正例为明确“感兴趣”，负例为明确“不感兴趣”；曝光未点击、必去选择和自动加入不得直接作为对应标签。
3. 在服务端生成固定支持域、米制网格、归一化密度及 50%/80%/95% 区域，输出完整哈希与原因字段。
4. 接入只读接口、连续区域和必去覆盖层；测试新图层与现有草稿、预览、接受、撤销和双地图共存。
5. 通过下面的证据门槛后再决定默认开启。真实反馈覆盖不足或模型未校准时，只发布明确标注的先验/相对兴趣模式，不升级成经验证的概率功能。

代码工作量粗估：单日外观与只读探索闭环约 4–7 个工作日；包含离线拟合、校准评估和正式区域数值验证约 8–15 个工作日。均为单人熟悉仓库后的工程估计，包含集成但不包含等待真实用户反馈的日历时间，也不表示已排期。

## 失败处理与可观察证据

模型、目录、支持域或反馈缺失时只隐藏本图层并显示具体原因，现有路线及核心行程操作继续工作。无可选 POI、只有必去点、候选被截断和积分为零各自有明确状态。过期或乱序响应丢弃，不允许旧区域覆盖新行程。计算设网格/候选上限、请求超时和 UI 取消；同一输入与种子应可复现。

沿用当前接口错误和地图诊断记录 `model_id`、候选数量、截断状态、积分误差、支持域、质量等级、耗时及失效原因，不记录原始个人聊天。回滚只关闭新图层并移除其源/层，不修改接受行程。

## 验证与验收

- 数值：概率在 [0,1]，区间有序，固定输入可复现；非空密度积分误差目标不超过 1e-3；网格离散度满足 `mass(R_c)>=c` 且超出不大于一个边界网格质量（并列阈值单独报告）。固定规则下区域保持嵌套。跨水域/无支持域不造热点。
- 统计：按用户和时间设计独立训练、校准、最终测试集，防止同一用户/POI 泄漏；与当前效用排序及简单概率基线比较。报告 Brier、log loss、可靠性图及每档样本量，不能仅凭一个总分宣布校准成功。若重复会话相关性存在，以用户为单位评估或分组，保留分群误差。
- 约束：最深色必去点不随偏好滑块、模型概率、缩放或区域等级变淡；不向区域注入伪概率；硬属性约束和仅被选中的候选点不得误显示为必去。冲突必去点保留并有文字说明。
- 集成：接口零接受行程变更；认证、revision、行程 hash 及路线依据一致；区域不使用 top-10 截断结果冒充完整集合。兴趣估计不能绕过 candidate_burden 的推荐资格检查。
- 浏览器：1440px 和 390px；开关、详情、键盘、图例、缩放平移、切换日程、接受/撤销、重载、乱序响应、地图销毁重建。记录截图与实际渲染层，不只检查源数据。
- 性能目标：本地 500 个候选、128×128 网格的 warm 请求 p95 < 500ms，显示层切换无长时间阻塞；这是拟议目标，需实测后调整，尚非结果。

## 后续研究条件

若需要“真实选择位置有 90% 长期覆盖率”的表述，先定义真实响应和支持集，再考虑 conformal prediction。独立校准数据以及校准/未来样本的交换性等条件必须成立；通常保证是边际覆盖，不是每个用户每次都覆盖。经地理掩码裁剪、筛候选或只保留某一峰后需要重新审查保证。[Conformal prediction 教程](https://arxiv.org/abs/2107.07511)。

若后续要让概率进入求解目标，可分别研究期望效用、风险厌恶和机会约束。天气/旅行时长的不确定性需要独立分布及可行性评估，不能由兴趣概率替代。该部分不纳入本功能首版。

当前状态以文档开头的检查点记录为准。完成代码、数值/浏览器验证和统计验证是不同门槛；这里没有把真实用户校准、默认注册表修复或研究 gate 标为完成。概率校准定义参考 [scikit-learn 官方文档](https://scikit-learn.org/stable/modules/calibration.html)。
