# Current Project Notes

This folder holds current-implementation audits and problem notes that are useful for claims control but are not themselves literature-review matrices.

## Files

- `current_problem_manifest.md`: authoritative current implementation-status table; use it instead of inferring completion from historical reports or artifact presence.
- `current_score_audit.md`: audit of the current repository scoring model, including safe claim language, limitations, and repair-paper implications.
- `e1_authoritative_entrypoint_closeout.md`: package-entrypoint and thin-notebook closeout evidence.
- `e2_raw_comparison_status.md`, `e2_route_bundle_preflight.json`, and `route_evidence_readiness_audit.md`: closed E2 identity, reviewed route evidence, and strict Phase 0 result.
- `local_osrm_readiness.md` and `local_osrm_candidate_approval.md`: approved pinned deployment, provider provenance, and accepted local-routing evidence.
- `e3_method_semantics.md`: locked information boundary and objective semantics for the four benchmark methods.
- `e3_publication_benchmark_contract.md`: implemented E3 evidence and ranking contract; its structurally publication-ready bundle is not a complete four-method performance comparison, and E3.1/E3.3 remain blocked in the status authority.

## Relationship to Literature

The compact repair-gap literature matrix lives in `docs/literature/literature_matrix_repair_gap.md`. Keep that matrix with the literature materials because it compares papers and identifies the research gap. Keep implementation audits here because they describe what the current project can and cannot honestly claim.
